# 食品营销合规审校

界定食品配料、商标、广告材料与审查证据的关系，并提供营销合规审校后台：
每条表达绑定证据版本，明确普通食品与药品功效的边界，投诉可以一路核对到
实际素材、审核依据和后续行动。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json`
给出可公开使用的示例。代码库只负责读取与校验这些资料，业务服务可沿用相同
标识和版本约定。

当前资料反映的事实包括：

- 产品属于普通食品
- 商品配料与消费者熟悉的同名药品不同
- 抽检合格与营销合规不是同一结论

## 审校后台（`src/compliance/`）

- `models.py` — 不可变记录：产品、渠道、证据版本、法规版本、表达、审核、
  发布、处置、投诉。所有记录只增不改。
- `policy.py` — 审核权限（哪些角色必须并行审批哪类表达）与表达-证据匹配
  策略（哪类话题需要哪类证据）。
- `store.py` — 只增不删的记录仓库；下线、处置均以追加记录表达。
- `service.py` — 核心服务：评估、发布、按“渠道 + 日期”复原页面、追加处置。
- `reports.py` — 影响分析与投诉追踪。
- `seed.py` — 从种子资料装载完整后台（格式见
  `contracts/compliance-seed.schema.json`，示例见
  `fixtures/compliance_seed.json`，全部为虚构数据）。

### 设计约定

- **每条表达绑定证据版本**：发布时逐条核对绑定证据在发布日是否“当时适用”
  （在有效期内且未被更新版本取代）。
- **单一证据不放行全部宣传**：注册商标、抽检合格等只覆盖各自话题；表达的
  话题决定所需证据种类，缺一即拦截。
- **普通食品与药品功效的边界**：法规按生效日更替；普通食品使用药品功效
  表达（或新规禁止的混淆性功效表述）即违规，与证据是否齐全无关。
- **并行审批按角色与渠道授权**：所需角色全部通过才算审结；审核之后证据
  或法规发生变化，审核自动标记失效；跨渠道复用需重新授权。
- **处置只追加**：下架、澄清、修改（产生新素材版本）都是新记录，历史页面
  在任何过去日期都可完整复原。
- **影响分析**：证据版本更替、法规生效日变化、旧图回流、跨渠道复用时，
  系统列出受影响的在架素材及原因。
- **投诉追踪**：`trace_complaint` 输出 JSON 报告，串联投诉 → 实际页面与
  表达 → 绑定证据版本状态 → 审核记录 → 当时适用法规 → 处置与后续行动。

## 本地校验

运行项目自带测试即可确认样例资料可读取，且领域标识与版本字段完整：

```bash
pip install -r requirements.txt
python -m pytest
```

演示投诉核对全流程：

```bash
python scripts/trace_complaint_demo.py
```

所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。
