# 食品营销合规审校

界定食品配料、商标、广告材料与审查证据的关系，并提供营销合规审校后台：每条对外表达绑定证据版本，处置只追加不抹去历史，外部条件变化时指出受影响的已发布素材。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json` 给出可公开使用的示例。代码库只负责读取与校验这些资料，业务服务可沿用相同标识和版本约定。

当前资料反映的事实包括：

- 产品属于普通食品
- 商品配料与消费者熟悉的同名药品不同
- 抽检合格与营销合规不是同一结论

## 审校后台（src/compliance）

`fixtures/` 下的虚构样例覆盖产品、成分、渠道与审核权限：

- `products.json` / `evidence.json`：普通食品喉糖与同名口服液（药品），配料表、商标注册证、抽检报告、法律意见各自按版本与有效期生效
- `claims.json` / `materials.json`：每条表达（包装图文、广告话术、代言内容）绑定证据版本，素材按版本留存并以 `content_hash` 识别旧图
- `channels.json` / `publications.json`：渠道限制与投放窗口，可按日期复原任一渠道当时展示的素材版本
- `reviews.json` / `permissions.json`：审核结论、引用证据与角色权限（法务/质量/市场）
- `dispositions.json` / `complaints.json` / `regulations.json`：只追加的处置记录、投诉与法规生效日

模块能力：

- `rules`：普通食品不得命中药品功效禁用词、不得与药品对比混淆；各表达类型有必需证据种类，注册商标或抽检合格不能单独替所有宣传放行；审核角色不得越权
- `store`：只追加记录库，下架、澄清、修改均体现为新的处置记录，历史发布页面保持原样
- `impact`：旧图回流、跨渠道复用、并行审批冲突、法规生效日变化时，指出受影响的已发布素材及其当日状态
- `trace`：从投诉一路核对到实际素材、表达绑定的证据版本、审核依据和后续处置

## 本地校验

运行项目自带测试即可确认样例资料可读取，且领域标识与版本字段完整。所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。

```bash
python -m pytest          # 单元测试
python -m src.compliance  # 打印投诉溯源报告与影响面分析
```
